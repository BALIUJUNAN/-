# 阶段 7：库存流水账本

## 目标

将 StockLog 从运行时文本投影迁移为 AbyssDB 实体，使每次库存变化都有可重启、可索引、
可审计的持久记录。销售完成时，订单、商品库存、会员数据和出库流水必须在同一个 UOW
中提交；`stock_log.txt` 只保留为首次迁移输入。

## 已实现

- StockLog 使用稳定整数实体：数量和变动前后库存为千分单位，时间为 `int64_t`。
- 版本化 TLV codec 校验必需字段、字符串边界、数量范围和损坏输入。
- 主键 `a0`、商品时间 `a1`、类型时间 `a2` 三个命名空间已接入仓储。
- 商品与类型组合查询使用商品索引限定范围，解码后再应用类型过滤，不混拼物理前缀。
- 流水 ID 使用持久化 counter，显式迁移会推进 counter 水位。
- 独立阶段 7 迁移标记支持重复启动；坏行、冲突或提交失败时数据与标记一起回滚。
- 销售结算在扣减 Product 后、完成 Sale 前写入出库流水，任一步失败都会回滚全部实体。
- `record_stock_log`、`query_stock_logs` 和成本报表已改为调用 service/repository。
- 运行时不再加载、保存或备份 `stock_log.txt`。

## 事务不变量

1. 每条流水的主记录和两个二级索引必须一次提交。
2. 销售库存不足时不得生成流水，也不得改变订单、商品或会员。
3. 成功销售的每项合并库存扣减恰好生成一条出库流水。
4. 流水数量、变动前库存和变动后库存使用千分单位，转换溢出必须拒绝整个事务。
5. 已迁移的 `stock_log.txt` 不再被运行时读取或写入。

## 验收

`make test-phase7` 覆盖：

- codec round-trip、三种索引查询、商品与类型组合筛选以及 reopen 一致性。
- 库存不足时销售、商品和库存流水完整回滚。
- 成功销售同时提交订单、库存和出库流水。
- 旧流水精确保留 ID，并从历史最大 ID 继续分配。
- 重复迁移跳过；坏行不写数据或迁移标记，修复后可以重试。

## 阶段边界

本阶段只迁移全局 StockLog 账本。Batch/FIFO 与采购收货已在阶段 8 纳入数据库事务；
门店库存和调拨仍将在对应聚合阶段实现，AuditLog 仍待审计阶段迁移。
