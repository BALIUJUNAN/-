# 阶段 8：采购聚合与批次 FIFO

## 目标

将 Purchase、PurchaseItem 和 Batch 迁移到 AbyssDB，并把采购收货从逐商品提交改为
一个业务事务。收货成功必须同时更新采购状态、明细实收量、商品库存、批次和库存流水；
任一步失败不得留下半入库。

## 已实现

- Purchase、PurchaseItem、Batch 使用版本化 TLV；金额为整数分，数量为千分单位。
- 采购主键、状态、供应商时间和明细前缀索引使用 `b0-b3` 命名空间。
- 批次主键、商品到期和商品收货时间索引使用 `66-68` 命名空间。
- 批次保存来源采购 ID 和明细 ID，自动批号由持久化 counter 分配。
- 采购状态机限制为 Pending -> Approved/Rejected，Approved -> Completed。
- 审批时从持久化明细重新计算总额，空订单不能审批。
- 收货在同一 UOW 中更新 Purchase、PurchaseItem、Product、Batch 和 StockLog。
- 商品库存仍是整数单位，因此当前收货拒绝不能精确换算为整数单位的采购数量，不再静默截断。
- 销售商品存在批次账本时，在原销售 UOW 中按收货时间 FIFO 扣减批次；批次不足整单回滚。
- 没有批次历史的旧商品继续使用 Product 库存，保证迁移过渡期兼容。
- `purchase.txt`、`purchase_item.txt`、`batch.txt` 只作为首次迁移输入。

## 迁移协议

- 阶段 8 使用独立迁移标记 `{migration namespace, 0x08}`。
- 三个源文件先全部解析和校验，再在一个 UOW 中写入实体、索引、counter 和标记。
- 采购主记录或批次重复时最后一条记录生效，兼容旧追加更新格式。
- 坏行、引用冲突或提交失败时不保留任何阶段 8 数据或迁移标记。
- 无标记但目标命名空间已有数据时拒绝自动导入，避免混合两套事实来源。

## 事务不变量

1. 非 Pending 采购不能增加明细，也不能再次审批或拒绝。
2. 非 Approved 采购不能收货，Completed 采购不能重复入库。
3. 明细实收量不能超过订购量，成功收货后两者相等。
4. 批次当前量不能为负，也不能超过初始量。
5. 存在批次账本时，销售扣减必须同时满足 Product 和 Batch 两套库存。
6. FIFO 顺序由 `product_id + received_at + batch_no` 物理索引决定。

## 验收

`make test-phase8` 覆盖：

- 三种实体 codec、采购状态索引、明细前缀和批次 FIFO 索引。
- 收货处理中遇到缺失商品时，已处理商品、明细、批次和流水全部回滚。
- 成功收货一次提交订单、商品、实收量、批次和入库流水。
- Product 足够但 Batch 不足时销售回滚；批次足够时按 FIFO 与销售一起提交。
- 三文件迁移坏行回滚、修复重试、重复启动跳过和 reopen 一致性。

## 阶段边界

供应商应付账款已在阶段 9 纳入收货 UOW；审计日志仍将在最终审计阶段迁移。
门店库存和调拨有独立库存维度，不在本阶段复用全局 Product/Batch 事务。
