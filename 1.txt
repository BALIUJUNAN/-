【开篇：这个系统是什么？】

想象一下你开了一家超市。你需要：
- 登记员工谁上班、谁下班
- 记录货架上有什么货、卖了多少钱
- 给会员打折、搞促销活动
- 打印购物小票给顾客

这个C语言程序就是帮你做这一切的"电脑管家"。它不需要数据库，所有数据都存在普通的文本文件里（就像你用记事本写的清单），用竖线 "|" 分隔每个信息。

比如员工数据文件 employee.txt 里的一行：
    1|张三|收银员|a3f2...|x9k1...|1|1716000000|1716000000

这行的意思是：员工编号1、名字张三、角色收银员、密码哈希值、盐值、在职状态、创建时间、更新时间。


================================================================================
第一关：认识数据结构（supermarket.h）
================================================================================

【学术解释】

supermarket.h 是整个系统的"蓝图"，就像建筑的图纸。它用C语言的 struct（结构体）定义了系统中所有"东西"长什么样。

【生活类比】

想象你在填各种表格：

1. 员工登记表（Employee结构体）：
   - 编号：1
   - 姓名：张三
   - 角色：收银员（还有库管、店长、管理员）
   - 密码：不是明文存的，而是用SHA-256加密后的乱码
   - 状态：在职或离职

2. 商品登记表（Product结构体）：
   - 商品编号：P001
   - 名称：可口可乐330ml
   - 条形码：6901234567890
   - 零售价：3.50元
   - 进价（成本）：2.00元
   - 当前库存：100瓶
   - 最低库存预警：20瓶（低于这个数就该进货了）
   - 状态：上架或下架

3. 销售订单表（Sale结构体）：
   - 订单编号：1001
   - 收银员编号：1
   - 会员编号：0（0表示非会员）
   - 总金额、折扣、实付金额
   - 支付方式：现金/支付宝/微信
   - 状态：挂单/完成/退款

4. 会员登记表（Member结构体）：
   - 会员编号、手机号（用来查会员的"钥匙"）
   - 姓名、等级（普通/银卡/金卡/钻卡）
   - 积分余额、累计消费金额

整个系统一共定义了约20种这样的"表格"，涵盖了超市运营的方方面面。

【重点概念】

- struct（结构体）：把相关的数据打包在一起。就像一张表格，每一行是一个具体的人/物/事。
- 每个结构体里都有一个 next 指针：这是为了把多个结构体连成一条"链子"（链表），就像火车车厢一节连一节。
- 宏定义（#define）：给数字起个好记的名字。比如 #define STATUS_ACTIVE 1，以后写 STATUS_ACTIVE 就等于写 1，代码更易读。


================================================================================
第二关：哈希表 - 超快的查找工具（hash.h + supermarket.c）
================================================================================

【学术解释】

哈希表（Hash Table）是一种数据结构，能实现"输入一个名字，瞬间找到对应的记录"，时间复杂度是 O(1)——不管数据有多少，查找速度一样快。

【生活类比】

想象超市的储物柜：
- 你存包的时候，管理员根据你的名字算出一个柜子编号（比如"张三"算出编号5381）
- 取包的时候，再算一次，直接去5381号柜子拿就行了
- 不用一个一个柜子翻找

哈希表的工作原理就是这样：
1. hash_insert(表, "可口可乐", 商品指针) -- 把可口可乐的信息存进去
2. hash_search(表, "可口可乐") -- 瞬间找到可口可乐的信息
3. hash_delete(表, "可口可乐") -- 删除这条记录

【代码中的实现】

hash.h 定义了两个核心结构：
- HashNode（哈希节点）：存一个键值对，key是名字，data是指向实际数据的指针，next指向下一个冲突的节点
- HashTable（哈希表）：一个指针数组（桶），每个桶可以挂多个节点

系统用 djb2 算法把字符串（比如商品条码）转换成一个数字，再对10007取余，得到桶的编号。
为什么是10007？因为它是质数，能让数据分布更均匀，减少冲突。

【系统用了哪些哈希表？】

- g_employee_hash：通过员工姓名快速找到员工信息
- g_product_hash：通过商品ID快速找到商品信息
- g_barcode_hash：通过条形码快速找到商品（扫码枪扫一下就找到）
- g_supplier_hash：通过供应商ID快速找到供应商
- g_member_phone_hash：通过手机号快速找到会员

这就像超市有好几本索引：按名字查、按编号查、按条码查，每种查法都是瞬间完成。


================================================================================
第三关：文件读写 - 数据怎么存到硬盘上（supermarket.c）
================================================================================

【学术解释】

本系统不使用数据库，所有数据以纯文本格式存储在 data/ 目录下，字段之间用 "|" 分隔。文件操作包括全量写入（atomic_write）和追加写入（atomic_append）。

【生活类比】

想象你用一个笔记本记账：
- 全量写入 = 把整页撕掉，重新抄一遍新的内容
- 追加写入 = 直接在最后加一行新记录

【关键函数】

1. atomic_write（原子写入）：
   步骤：先写到临时文件 → 确认写完 → 把临时文件改名为正式文件
   为什么要这么麻烦？如果写到一半停电了，原文件不会被破坏，因为原文件还没被替换。
   就像你要修改一份重要合同，先在草稿纸上写好，确认无误后再替换原件。

2. atomic_append（追加写入）：
   直接打开文件，在末尾加一行新内容，用文件锁保证同一时间只有一个人能写。
   这就像在公告栏上贴新通知，不用把旧通知全撕掉。

3. file_lock / file_unlock（文件锁）：
   Windows用 LockFileEx，Linux用 flock。
   就像厕所门上的锁——一个人进去了，别人得等。

4. read_lines（读取所有行）：
   把文件内容一行一行读到内存数组中，返回一个字符串指针数组。


================================================================================
第四关：工具函数 - 各种小帮手（supermarket.c）
================================================================================

【生活类比】

这些就像超市里的各种小工具：

1. trim(str)：去除字符串首尾的空格和换行符
   就像把一张皱巴巴的纸抚平，去掉多余的空白。

2. generate_salt(salt)：生成随机"盐值"
   什么是盐值？想象密码是"123456"，直接存太危险。
   盐值就像在密码后面加一把随机的调料："123456" + "x9k2m" = "123456x9k2m"
   这样即使两个人密码相同，加了不同的盐，加密结果也不同。

3. hash_password(密码, 盐值, 输出缓冲区)：
   用SHA-256算法把"密码+盐值"搅成一串64位的十六进制乱码。
   SHA-256的特点：正向算很容易，反向破解几乎不可能。
   就像把鸡蛋做成煎蛋——很容易，但你没法把煎蛋变回生鸡蛋。

4. generate_id()：全局自增ID
   每次调用返回一个新数字：1, 2, 3, 4... 保证不重复。

5. format_time(时间戳, 缓冲区)：
   把计算机的时间戳（一长串数字）变成人类能看懂的格式："2024-05-18 14:30:00"。


================================================================================
第五关：员工与商品的增删改查（supermarket.c）
================================================================================

【学术解释】

CRUD = Create（创建）、Read（读取）、Update（更新）、Delete（删除），是所有管理系统的基本操作。

【员工管理】

- add_employee(员工信息)：生成新ID，插入哈希表，保存到文件
- find_employee_by_id(编号)：在哈希表中查找
- update_employee(员工信息)：修改后重新保存
- delete_employee(编号)：不是真的删除，而是把状态改成"离职"（软删除）
  为什么要软删除？就像公司的人事档案——员工离职了，档案还是要保留的，以备查账。

- load_employees()：启动时从 employee.txt 读取所有员工数据，构建哈希表
- save_employees()：把内存中所有员工数据写回文件

【商品管理】

和员工管理类似，但多了一个"双索引"设计：
- 通过商品ID查：g_product_hash
- 通过条形码查：g_barcode_hash

这就像图书馆有两套索引：一套按书号查，一套按书名查，怎么查都方便。


================================================================================
第六关：系统入口与菜单（main.c）
================================================================================

【学术解释】

main.c 是整个程序的入口，负责初始化系统、登录验证、显示菜单、调度各功能模块。

【生活类比】

main.c 就像超市的"总控室"：

1. main() 函数 = 开店流程
   - 初始化界面 → 加载所有数据文件（15个文件！）→ 检查是否有管理员 → 显示主菜单 → 等待用户操作

2. login() = 员工打卡上班
   - 输入用户名和密码
   - 系统用 SHA-256 验证密码是否正确
   - 通过后记录"当前是谁在操作"

3. show_main_menu() = 收银台的操作面板
   - 显示16个功能入口（人员管理、商品管理、销售、采购、会员、促销等）
   - 用户输入数字或字母选择功能
   - 选择后跳转到对应的子菜单

4. check_permission() = 权限门禁
   - 不同角色能访问不同功能
   - 管理员 = 万能钥匙，哪里都能去
   - 收银员 = 只能用销售功能
   - 库管 = 只能用采购和库存功能

【菜单结构】

主菜单 → 各子菜单，每个子菜单是一个 while(1) 循环：
  while (1) {
      显示菜单选项
      获取用户输入
      switch (选择) {
          case 1: 执行操作1; break;
          case 2: 执行操作2; break;
          case 0: return;  // 返回上级菜单
      }
  }


================================================================================
第七关：界面模块（ui.c / ui.h）
================================================================================

【学术解释】

UI模块负责所有屏幕输出和用户输入，与业务逻辑完全分离。这样做的好处是：如果以后想换一套界面（比如换成图形界面），只需要改UI模块，不用动业务代码。

【生活类比】

UI模块就像超市的"装修"：

1. 颜色系统：
   - print_success = 绿色文字（操作成功）
   - print_error = 红色文字（操作失败）
   - print_warning = 黄色文字（警告提示）
   - 就像交通灯：绿灯行、红灯停、黄灯注意

2. 边框绘制：
   - print_title_box() 画一个双线边框的标题栏
   - 自动处理中文字符宽度（一个中文占两个英文字符的位置）

3. 安全输入：
   - get_safe_int()：获取整数，带范围验证（比如只能输入1-100）
   - get_password_input()：输入密码时显示 * 而不是明文
   - get_yes_no()：确认操作（y/n）

4. 表格绘制：
   table_begin → table_draw_header → table_draw_row → table_end
   就像画一个Excel表格：先定义列，再画表头，然后一行一行填数据。

5. 分页显示：
   商品列表可能有几百条，一屏显示不下，就分成多页，用上下键翻页。


================================================================================
总结：第一部分的核心要点
================================================================================

1. supermarket.h 是蓝图：定义了系统中所有数据的"表格模板"
2. hash.h 是快速索引：让查找速度从"一个一个翻"变成"瞬间定位"
3. supermarket.c 是基础设施：文件读写、密码加密、员工/商品的增删改查
4. main.c 是总控室：登录、菜单、调度各功能模块
5. ui.c 是界面层：画边框、显示颜色、安全输入、表格渲染

记住一句话：supermarket.c 提供工具，main.c 用这些工具搭建菜单，ui.c 负责让一切看起来漂亮。

所有模块都通过 #include "supermarket.h" 来共享数据结构和函数声明，就像所有人都看着同一份图纸施工。
